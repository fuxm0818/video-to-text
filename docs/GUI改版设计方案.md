# 视频转文字 · 界面改版设计方案 v2.1

> 面向 `/Users/fuxiangming/Agent工作空间/视频转文字/video-to-text` 现有 PySide6 桌面 App 的视觉与交互重做。
> 转写内核（core / docx）不动；`jobs.py` 只做数据字段与参数的小幅扩展，不重写调度器。
> 目标：让它看起来像一台机器上该有的**工具**，而不是一个网页落地页。

---

## v2.1 修订口径（2026-10-30，与代码核对后，以此为准）

v2 的诊断和视觉方向保留，以下 7 条按实际代码修正，实施时以本节优先：

1. **停止 = 立即停止。** `JobManager.cancel()` 现在会设置取消事件并终止 worker 进程（`jobs.py:324`、`jobs.py:612`），当前文件作废。不改造成「等当前文件跑完」——长视频可能还要跑十几分钟，且会丢失已跑的识别进度（模型在每个 worker 进程内缓存复用，`core.py:293`，不是「只浪费一次模型加载」）。按钮文案与 tooltip 如实写「立即停止，当前文件不会留下产物」。
2. **运行中不允许添加 / 移除队列。** `add_paths/remove/clear` 在 running 时直接抛错（`jobs.py:167`），`start()` 一次性灌任务再塞结束符（`jobs.py:442`）。v2.1 不重写调度器：运行中禁用工具栏添加/移除与拖拽，tooltip 说明「停止后可继续」。
3. **取消「单文件百分比」。** 已核对 FunASR 1.4.16 源码：`progress_callback` 只在 `AutoModel.inference()` 内部按批回调（`auto_model.py:702/848`），VAD 路径对每个 VAD 批次重新计数，不能表达整文件进度。因此：状态第二行显示「阶段 + 已用时」，状态条整体进度按**已完成文件的时长加权**，倍率与剩余时间用已完成文件推算并标「预计」。不显示任何假的 38%。
4. **模型下载字节进度** 通过轮询 `~/.cache/modelscope` 目录大小得到（`jobs.py` 里实现），总量按约 2.1 GB 名义值，剩余时间标「预计」。下载 sheet 只在任务进入模型准备/下载阶段时出现，非模态，主窗口仍可查看；关闭 sheet 后可从状态条「查看下载进度」重新打开。取消 sheet 等于取消本次任务。「下载期间可继续排队」不实现（与第 2 条一致）。
5. **图标着色 helper 需要新写。** 现有 `_asset_icon` 只是 `QIcon(path)`（`gui.py:95`），没有颜色变量替换。行动作图标用 SVG + 生成时替换 `%ICON_COLOR%`；状态图标用 `QPainter` 绘制（含运行中旋转），减少 7 个 SVG。
6. **测试必须重写。** `tests/test_ui.py` 断言的是旧控件（`start_button/table_stack/output_dir_edit/file_count`）。验收的「unittest 全绿」包含重写后的 UI 测试。
7. **小项修正**：侧边栏筛选增加「已跳过 / 已取消」；跳过行文案写「输出已存在」（跳过条件不是单纯同名，见 `jobs.py:284`）；补充菜单栏结构（`⌘,` 需 `PreferencesRole` 才能进 macOS 应用菜单）；最小窗口宽改为 900；§10.2 的「现有转写时才探测时长」不成立——`add_paths` 已经在后台线程 `probe_duration`（`jobs.py:193`）。

## 0. 为什么要改：现有界面的"AI 味"体检

现有界面（`docs/screenshot.png`，样式表见 `src/video_to_text/theme.py`）功能完整，但它的视觉语言有一整套固定特征，这套特征在 2024–2026 年间被大量生成式界面反复复用，已经形成了条件反射式的辨识度。逐条拆开：

| # | 现有做法 | 为什么会被一眼认出 | 判定 |
|---|---|---|---|
| 1 | 米白底 `#f4efe6` + 砖红强调 `#a23b2a` | 「暖陶土 / 莫兰迪暖色系」是生成式界面的默认安全牌：低饱和暖灰底 + 一个偏红的强调色，几乎成为模板 | **主因** |
| 2 | 顶部大 header 区：图标 + 英文 eyebrow `VIDEO ➜ TEXT`（`letter-spacing:2px`）+ 22px 大标题 + 营销副标题「把视频里的每一句话，变成可以读的文字」 | 这是 landing page 的 hero 区结构。桌面工具把首屏 1/4 高度让给自我介绍，是网页思维，不是工具思维 | **主因** |
| 3 | `01 选择素材 / 02 输出设置 / 03 转写进度` 编号步骤卡 | 「三步走」编号叙事同样来自落地页的 "How it works" 区 | **主因** |
| 4 | 按钮与列表里用 emoji 图标 `⊕` `📁` `▶` `›` `×` | emoji 当图标是生成式 UI 的标志性偷懒。原生应用不会在按钮里放彩色 emoji | **主因** |
| 5 | 右上角绿色胶囊徽章「仅在本机运行」+ 绿点 | 状态胶囊（badge pill）堆叠是 Web dashboard 语言 | 次要 |
| 6 | 底部四个大数字统计卡 `1 完成 / 0 失败 / 0 跳过 / 0 取消` | 数字+小字说明的 stat cell 是 dashboard 组件，工具里不该做展板 | 次要 |
| 7 | 三张圆角 12px 白卡片 + 描边 + 阴影，浮在米色底上 | 卡片化（card-based）布局是 Web 的，macOS 原生是「整片内容区 + 细分隔线」，不叠卡片 | 次要 |
| 8 | 文案带推销腔：`M4A · 推荐，体积小`、`1 个文件 → Markdown + Word + M4A 音频` | 「推荐」标签和箭头推导句式是营销页话术 | 次要 |
| 9 | 只有浅色一套配色，无深色模式 | 2026 年的 macOS 专业工具不支持深色，会被直接归为原型 | 次要 |
| 10 | `Ctrl+Enter 开始` 写在按钮下方 | 快捷键提示属于菜单/工具提示，不该印在按钮旁 | 轻微 |

**结论**：问题不在"丑"，在于它使用了错误的**体裁**。它的信息架构其实是对的（选素材 → 设输出 → 跑 → 看结果），错的是把这套架构套进了落地页的视觉体裁里。改版的核心动作是**换体裁**：从 Web landing page 换成 macOS 原生工具。

## 1. 设计原则（五条，后续所有决策以这五条裁断）

1. **它是工具，不是落地页。** 窗口里每一像素都要么是内容，要么是操作。删除一切自我介绍。
2. **系统优先，少自绘。** 能用系统控件的不要自己画；颜色能取系统的就取系统的（尤其强调色跟随系统 accent）。自绘越少，越像这台机器上长出来的东西。
3. **说人话，不推销。** 界面文案是给用户下指令和报状态，不是招揽用户。删掉所有形容词与"推荐"。
4. **状态必须可解释。** 批处理工具最大的焦虑是黑盒。用户随时要知道：现在在跑哪个、跑了多久、多快、还要多久、失败的那个为什么失败。
5. **深色模式是一等公民。** 不是"补一个深色主题"，而是所有 token 从一开始就是成对的。

## 3. 信息架构

```
视频转文字（主窗口）
├─ 统一工具栏        [添加 ▾] [移除] │ [开始转写 / 停止] │ spacer │ [⚙]
├─ 主体（QSplitter）
│   ├─ 侧边栏 200px  队列筛选 / 输出（位置与格式）
│   └─ 素材表        状态 · 名称 · 时长 · 大小 · 用时 · 产物
├─ 状态条           左侧汇总 / 中间进度 / 右侧动作
└─ 日志抽屉（⌘L，从状态条上方升起，默认收起）

偏好设置（⌘,）       输出 / 格式 / 性能 / 一般
首次运行：模型下载   独立模态 sheet，不可跳过，可取消，可后台
关于（⌘I 或 菜单）    版本 · 许可 · 隐私一句 · 第三方声明入口
```

窗口职责划分的原则：**主窗口只做"这一批任务"**，所有"以后都这样"的设置进偏好设置窗口。现在把"高级选项（并发数）"塞在主窗口是错的——并发数是机器属性，不是任务属性。

## 4. 主窗口详细设计

### 4.1 窗口 chrome

| 项 | 值 |
|---|---|
| 默认尺寸 | 980 × 660；最小 900 × 600 |
| 标题栏 | macOS 统一工具栏（`setUnifiedTitleAndToolBarOnMac(True)`），工具栏高 38pt |
| 工具栏内容 | `添加 ▾`（带下拉：文件/文件夹）、`移除`、`分隔`、`开始转写`（主按钮，运行中变 `停止`）、弹性 spacer、`⚙`（打开偏好设置） |
| 工具栏按钮样式 | 图标在上文字在下（`ToolButtonTextUnderIcon`），11px 文字；或纯图标 + tooltip（推荐纯图标，更接近 Finder） |
| 标题 | 窗口标题「视频转文字」；有未完成任务时标题可加圆点标记（macOS 文档编辑标记） |
| 窗口状态记忆 | 尺寸 + 位置 + 侧边栏宽度 + 日志抽屉开合（已有 `_load_window_state` 保留） |

Qt 无法拿到真正的 `NSVisualEffectView` 毛玻璃侧边栏。**诚实做法**：侧边栏用不透明实色（浅 `#F2F1F0` / 深 `#232325`），右下加 1px 分隔线。不要尝试用半透明白伪造毛玻璃——在浅色壁纸上会糊，是明显的山寨痕迹。

**菜单栏**（v2.1 补全）：`文件`（选择文件 ⌘O、选择文件夹 ⇧⌘O、打开输出文件夹、清空列表、关闭窗口 ⌘W）、`编辑`（移除选中 ⌫）、`任务`（开始转写 ⌘⏎、停止 ⌘.）、`显示`（查看日志 ⌘L、打开日志文件 ⌥⌘L）、`设置`（偏好设置 ⌘,，必须是 `PreferencesRole` 才能进 macOS 应用菜单）、`帮助`（关于，`AboutRole`）。菜单快捷键与工具栏按钮指向同一个 `QAction`，避免两套状态。

### 4.2 侧边栏（200px，可折叠）

- 分组标题 11px / 600 / 次要色，**正常大小写，不加 letter-spacing**。
- 选中项：圆角 6px 填充（浅色 `#E3E2E1` / 深色 `#3A3A3C`），文字转主色。未选中项纯文字无背景。
- 计数右对齐等宽数字，次要色。
- 「输出」分组两行可点击：点「位置」弹目录选择器；点「格式」打开偏好设置的格式页。
- 侧边栏底部留空，不放按钮。

**列定义**

| 列 | 宽 | 对齐 | 内容 |

**行规格**：行高 44px（两行文本），分隔线 1px 只画在行间、不画在最后一行；选中行填充圆角 6px + 主色文字（不要整行铺满的蓝底铺到边缘，留出 4px 内缩）。

**空态**（内容区居中，不放任何插画）：
```
        ⌄ （32px 线性拖放图标，次要色）
      把视频或音频拖到这里
      支持 mp4 / mov / mkv / mp3 / m4a / wav 等，文件夹会递归读取
      [ 选择文件… ]  [ 选择文件夹… ]
```
空态文案是**唯一**允许写功能说明的地方，且必须是一句平铺直述。

**拖拽**：整个内容区（含空态）是放置目标。`dragEnter` 时内容区整体加深底色 + 内缩 1px 虚线描边（2px 圆角 8px），**不要**在鼠标位置画动画光圈。

**右键菜单**：在访达中显示 / 打开文稿 ▸（MD、DOCX）/ 重新转写 / 复制路径 / 移除（⌫）。

### 4.4 输出设置（从主窗口迁出）

- 主窗口不再有「输出设置」卡片与「高级选项」折叠区。
- 输出位置与格式汇总显示在侧边栏「输出」分组（见 §4.2），点击即改。
- 并发数（1–4）进偏好设置「性能」页，附一句实测说明：*并发 2 提高总吞吐但更吃内存，16 GB 建议 1–2*。

理由：这些是"机器和习惯"，不是"这一批"。主窗口只留任务。

### 4.5 状态条（替代底部进度卡片）

状态条是**一行**，高 26px，背景同侧边栏，上方 1px 分隔线。左中右三段：

```
左（弹性）│ 中（固定 220px）│ 右（自适应）
```

**空闲 / 就绪**
```
12 个文件 · 2:13:40 · 1.4 GB                      输出：Markdown + Word + M4A
```

**运行中**（这是本次改版交互提升最大的一处）
```
正在转写 7/12 · demo_kokoro.mp4 · 识别中 00:42   ▓▓▓▓▓▓░░░░ 62%  5.8× 实时 · 预计还剩 8:20
```
四个信息缺一不可：**当前文件序号与文件名/阶段**、**总进度**、**实时倍率**、**剩余时间**。批处理工具里，用户真正焦虑的是"还要多久"，而不是"完成了几个"。

进度口径（v2.1）：总进度 = 已完成文件的时长 / 全部文件时长；当前文件在完成前不计入，避免假进度。倍率 = 已完成文件的素材时长 / 任务墙钟；剩余时间 = 未完成文件时长 / 倍率，明确标注「预计」，刚开始样本不足时显示「预计中」。

**完成**
```
完成 11 · 跳过 0 · 失败 1      共 00:27                    [在访达中显示] [查看日志]
```

**已取消**
```
已取消 · 完成 6，未开始 6                                   [继续未完成的]
```

进度条规格：高 4px（不要 10px），圆角 2px，宽度 120px 固定，轨道色 `#D8D7D5` / `#3A3A3C`，填充用系统 accent。不确定进度用 60px 宽的条形滚动（不要用转圈 spinner）。

### 4.6 日志抽屉

- 快捷键 `⌘L` 或点状态条「查看日志」，从状态条上方升起，高 180px，可拖高到 320px。
- 等宽字体 11px，行内前景色分级（信息=次要色，警告=橙，错误=红），不加时间戳前缀（日志里已有），不加背景块。
- 顶部一行：`运行日志` + 右侧「打开日志文件」。
- 自动滚到底，用户手动上滚时暂停自动滚动并浮现「回到最新」小按钮。

## 5. 配色 Token（light / dark 成对）

所有颜色定义为常量，QSS 由这些常量生成（见 §14）。**强调色不写死**，运行时取 `QPalette.Accent`（平台没有独立 accent 时回退 `QPalette.Highlight`）。macOS 上 `Highlight` 是文本选中底色（浅蓝），直接拿来做按钮会发灰发白，所以不用它。

### 浅色

## 6. 排版

| 用途 | 字号 | 字重 |
|---|---|---|
| 表格文件名、正文 | 13px | 400 |
| 表格第二行、列头、侧边栏计数、状态条 | 11px | 400 |
| 侧边栏分组标题 | 11px | 600 |
| 日志 | 11px 等宽 | 400 |
| 按钮 | 13px | 400（主按钮 590） |

- 字体族：macOS 用系统默认（`.AppleSystemUIFont` / PingFang SC），Windows 用 `Segoe UI` / `Microsoft YaHei UI`。Qt 里**不要写死 font-family**，让 Qt 走系统默认最安全；只在日志等宽处显式指定 `ui-monospace, SFMono-Regular, Menlo, Consolas`。
- **字重上限 600**。不要 700/800 的粗体标题——那是 Web hero 的残留。
- **禁止 letter-spacing**。任何加字距的全大写英文小标签都是 AI 味标志位。
- 时长、大小、百分比、计数一律用**等宽数字**（tabular figures），否则运行时数字跳动。
- 行高：13px 文字配 18px 行高；11px 配 15px。

### 7.1 按钮

## 9. 状态机

```
empty ──拖入/添加──> ready ──开始──> running ──全部结束──> finished
                       ↑                │                     │
                       └──移除全部──────┤                     └──再添加──> ready
                                        ├──停止──> canceled ──继续未完成──> running
                                        └──（部分失败）──> finished(with errors)
```

| 状态 | 工具栏 | 侧边栏 | 状态条 |
|---|---|---|---|
| empty | 添加启用；移除、开始禁用 | 只显示「队列」分组，计数全 0 | 空态提示：`拖入文件开始` |
| ready | 全部启用；开始为主按钮 | 计数按待转写填充 | `12 个文件 · 2:13:40 · 1.4 GB` |
| running | 开始变 `停止`（样式不变红，只换图标与文字）；添加、移除与拖拽禁用 | 实时计数 | 见 §4.5 运行中 |
| canceled | `停止` 变回 `开始转写` | 完成/取消计数 | 见 §4.5 已取消 + `[继续未完成的]` |
| finished | 同上 | 完成、失败计数 | 见 §4.5 完成 |

**停止的语义要写明**：点击停止后进程立即终止，当前文件不会留下产物，已完成的输出保留，未开始的不再开始。这句话放进停止按钮的 tooltip，不要弹确认框。模型在每个 worker 进程内只加载一次并复用，停止会丢弃这个进程里已跑的识别进度，不只是「一次模型加载」。

## 10. 关键流程

### 10.1 首次运行：模型下载（v2.1 修订）

现在是主窗口里的一块黄色提示条（`QFrame#modelNote`）。改成一个**独立的非模态 sheet**，只在任务进入模型准备/下载阶段时出现：

```
                    首次使用需要下载语音模型
                    Paraformer 识别 953 MB · CT-Punc 标点 1.1 GB · VAD 4 MB
                    ▓▓▓▓░░░░░░  412 MB / 约 2.1 GB     预计还剩 3 分钟
                    下载位置：~/.cache/modelscope
                                        [ 取消 ]
```

要点：
- 显示**已下载字节数**与名义总量（轮询 `~/.cache/modelscope`），不要只显示"正在下载…"；剩余时间按已下载速率估算，标「预计」。
- 非模态：主窗口仍可查看、开日志、看偏好设置；队列编辑在运行中禁用（与 §9 一致）。
- 点「取消」等于取消本次任务；关闭窗口则 sheet 隐藏，状态条保留「查看下载进度」入口。
- 模型就绪后 sheet 自动关闭；已就绪时不再显示任何提示条——**没有消息就是好消息**。
- 不单独做「预下载」入口：下载由第一次点「开始转写」触发。

### 10.2 拖拽

1. `dragEnterEvent` 校验 `hasUrls()`，过滤出扩展名在支持列表内的；一个都不匹配时 `ignore()`（不要显示红叉）。
2. 接受后内容区整体加深底 + 虚线内描边。
3. `dropEvent` 后：目录递归展开（沿用现有 `_add_paths`），时长探测沿用现有的后台线程 `_probe`（`jobs.py:193`，添加后即异步探测）。
4. 重复添加同一路径：不重复入列，状态条提示 `已存在，未重复添加`（2 秒后自动消失）。
5. 运行中拖入：忽略并提示 `正在转写，停止后可添加`（与 §9 一致）。

### 10.3 取消与继续

- 立即停止会把正在跑的文件和未开始的文件都标为「已取消」（`jobs.py:_mark_canceled`）。
- 状态条出现 `[继续未完成的]`，点击后重新走一次开始流程：已完成的文件因输出存在自动跳过，未完成/失败的文件重跑。
- 不要提供"暂停"——worker 进程内模型虽已加载，但中断后进程被终止，恢复要重新加载并丢失已跑进度，代价高于收益。

### 10.4 失败处理

- 失败行第二行显示错误摘要（截断到一行）。
- 点击该行左侧状态图标，行下方展开一段 11px 等宽灰字，显示完整 traceback 或错误文本 + `[复制]`。
- 右键菜单 `重新转写`，只重跑选中行。
- 常见错误要有**人话翻译**，这是最容易被 AI 生成界面忽略的：
  | 内核信号 | 界面显示 |
  |---|---|
  | 无音轨 | `文件没有音轨` · 补充：`可能是下载不完整，请重新下载后重试` |
  | ffmpeg 失败 | `无法读取音频` · 补充：`文件可能已损坏或格式不受支持` |
  | 磁盘不足 | `磁盘空间不足` · 补充：`需要约 X MB，当前可用 Y MB` |
  | 模型加载失败 | `语音模型加载失败` · 补充：`删除 ~/.cache/modelscope 后重新下载` |

### 10.5 打开产物

- macOS 用 `open`，Windows 用 `os.startfile`，Linux 用 `xdg-open`（沿用现有 `_open_output`）。
- 「在访达中显示」用 `open -R`（macOS）/ `explorer /select,`（Windows）。

### 14.2 主题与深色模式

```python
# tokens.py
LIGHT = {"bg.content": "#FFFFFF", "text.primary": "#1C1C1E", ...}
DARK  = {"bg.content": "#2A2A2C", "text.primary": "#F5F5F7", ...}

def palette(dark: bool) -> dict:
    return DARK if dark else LIGHT
```

注意：QSS 没有可靠的 palette 变量，强调色要在生成样式时把 `QPalette.Accent`（没有就取 `QPalette.Highlight`）转成字面色值；系统强调色变化（paletteChanged）时重建 QSS 并刷新图标。

跟随系统切换（Qt 6.5+）：

```python
hints = QGuiApplication.styleHints()
hints.colorSchemeChanged.connect(self._on_scheme_changed)

def _on_scheme_changed(self, scheme):
    dark = scheme == Qt.ColorScheme.Dark
    app.setPalette(build_palette(dark))        # 先设 QPalette，accent 由系统给
    app.setStyleSheet(styles.build(dark))      # 再刷 QSS
    for w in app.topLevelWidgets():
        w.style().unpolish(w); w.style().polish(w)
```

`build_palette()` 里**不要动** `QPalette.Accent` 和 `QPalette.Highlight` —— 让它们保持系统值，强调色就自动跟随用户在系统设置里选的强调色。这是"系统优先"原则最直接的落地，也是最能摆脱模板感的一招。

QSS 里凡是图标 URL，走生成时着色：

```python
def icon_url(name: str, color: str) -> str:
    src = (ICONS / f"{name}.svg").read_text(encoding="utf-8")
    src = src.replace("%ICON_COLOR%", color)
    tmp = CACHE / f"{name}-{color.lstrip('#')}.svg"
    tmp.write_text(src, encoding="utf-8")
    return tmp.as_uri()
```

### 14.3 macOS 统一工具栏

```python
self.setUnifiedTitleAndToolBarOnMac(True)
bar = QToolBar()
bar.setMovable(False); bar.setFloatable(False)
bar.setToolButtonStyle(Qt.ToolButtonStyle.ToolButtonIconOnly)
bar.setIconSize(QSize(18, 18))
bar.setStyleSheet("QToolBar{border:none;background:transparent;padding:4px 8px;}")
self.addToolBar(bar)
```

注意：统一工具栏下窗口标题由系统绘制在工具栏左侧，Qt 的 `setWindowTitle` 仍生效；不要再自绘标题区。若工具栏按钮太密导致标题被截断，把主按钮移到最右。

Windows 上 `setUnifiedTitleAndToolBarOnMac` 无效，工具栏退化为普通工具条——可接受，保持同一套按钮集合即可。

### 14.4 表格：状态列与展开错误行

沿用现有 `QTreeWidget` + `FileCellDelegate` 的思路，但：

- 状态列改为 `setIcon()` 而非自绘胶囊；图标按状态从 `icon_url()` 取。
- 错误详情作为该行的 **child item**，用 `setFirstColumnSpanned(True)` 让它横跨全宽，`setHidden(True)` 默认收起，点状态图标切换。
- 行高 44px 通过 `QTreeWidget.uniformRowHeights=False` + delegate 的 `sizeHint` 控制；错误子行高按文本行数动态算。
- 选中圆角 6px 需要在 delegate 的 `paint` 里画（`option.rect.adjusted(4, 2, -4, -2)` + `QPainterPath.addRoundedRect`），QSS 做不出内缩圆角。

### 14.5 等宽数字

```python
f = QFontDatabase.systemFont(QFontDatabase.SystemFont.GeneralFont)
f.setStyleHint(QFont.StyleHint.Monospace)   # 仅用于日志
# 表格里的时长/百分比：用 QFontMetrics 取最大字宽后 setFixedWidth，避免跳动
```

更简单可靠的做法：时长列右对齐 + 固定列宽，Qt 默认数字并非等宽，但右对齐下跳动不明显；若仍介意，对这几个 QLabel 用 `QFont("SF Mono")`/`Consolas` 单独设置。

### 14.6 风险点

| 风险 | 说明 | 处理 |
|---|---|---|
| 毛玻璃侧边栏 | Qt 拿不到 `NSVisualEffectView` | 用实色，不伪造 |
| 窗口圆角与阴影 | Qt 窗口在 macOS 上由系统给，OK | 不要自绘 `Qt.FramelessWindowHint` |
| 系统图标风格 | macOS 26 的图标更细，自绘 1.5px 描边接近 | 可接受 |
| 深色下 SVG 图标 | 必须两套颜色 | 由 `icon_url(name, color)` 生成两份缓存 |
| 打包 | 新增 SVG 要进 `packaging/video_to_text.spec` 的 datas | 用 `collect_data_files("video_to_text")` 已能覆盖 `assets/` |
| Windows 差异 | 统一工具栏、访达、`⌘` | 快捷键文案按平台渲染 `Ctrl`/`⌘`，已有类似处理可沿用 |
